# ADR-0004：原子文件输出与提交边界

- 状态：原型实现，待跨平台验证
- 日期：2026-10-20

## 背景

引擎执行失败或取消时，不应把半成品留在最终目标路径。输出生命周期仍由核心掌握，而不是由压缩器或解析器自行发布结果。

## 决策

`AtomicFileSink`：

1. 在最终目标的同一目录创建唯一临时文件。
2. 引擎只能通过受限 `OutputWriter` 写入临时数据。
3. 核心检查引擎输出类型、取消状态和资源限制，再刷新并同步临时文件。
4. 通过 `hard_link(temp, destination)` 发布最终路径。硬链接创建不覆盖现有目标；目标已存在时提交失败。
5. 发布成功后立即标记提交完成，再尝试删除临时名称。删除失败不会将已成功的发布报告为提交失败；会保留待清理状态，并在析构时重试。
6. 提交失败或收到放弃请求时，关闭临时文件并尝试删除临时路径。若提交失败后的清理也失败，会将清理错误附加到原始错误，并保留待清理状态供析构时重试。所有清理操作仍属于尽力而为，不保证在持续性文件系统错误下必然成功。

## 明确的保证与限制

- 在支持硬链接的同一文件系统中，最终文件名会在完整内容准备好后出现；不会用此实现替换已存在目标。
- 不支持硬链接的文件系统会令提交失败，需要为该平台实现并验证专用原子发布策略。
- 文件数据在发布前调用 `sync_all`；当前没有目录项跨平台持久化保证，不承诺突然断电后最终名称一定保留。
- 进程崩溃可能留下临时文件；当前版本没有启动时孤儿临时文件扫描器。
- `abort` 是尽力清理，而非所有存储后端都能保证回滚。
- 对象存储、标准输出和网络输出应采用不同的提交语义，不得直接假设具备文件式原子提交。

## 验证要求

必须测试目标已存在、磁盘写入失败、提交失败、取消、异常退出、文件系统不支持硬链接及跨平台行为。在这些测试完成之前，本实现是原型而非生产级持久化承诺。
